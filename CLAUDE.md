# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # start dev server on port 3000
npm run build        # route-clear → vite build → typecheck
npm run typecheck    # tsc type check only
npm run checkup      # typecheck + vite build (no route-clear)
npm run lint         # eslint
npm run lint:fix     # eslint --fix
npm run prettier:fix # prettier --write
```

> `build` deletes `src/app/routes/routeTree.gen.ts` first — this file is auto-generated by TanStack Router and must never be edited manually.

## Architecture

FSD (Feature-Sliced Design) with a strict module boundary enforced by ESLint `no-restricted-imports`. Imports must go through the public entry point of each module — never import from internal paths directly.

### Layer order (highest → lowest, can only import downward)

```
pages → widgets → features → entities → shared
```

### Module file naming conventions (from docs/arch.md)

Each module exposes one public entry: `{scope}.entry.ts` (replaces `index.ts`). Internal files follow fixed names:

| File                    | Purpose                      |
| ----------------------- | ---------------------------- |
| `{scope}.entry.ts`      | Public API / barrel export   |
| `{scope}.service.ts`    | Business logic and API calls |
| `{scope}.store.ts`      | State store logic            |
| `{scope}.component.tsx` | UI component                 |
| `{scope}.const.ts`      | Constants                    |
| `{scope}.contract.ts`   | Types / interfaces           |

### Import rule

The ESLint config enforces that all cross-module imports hit the entry file:

```ts
// ✅ correct
import { something } from "@/entities/plan/plan.entry";

// ❌ wrong — imports internal path
import { something } from "@/entities/plan/model/plan.contract";
```

Use `clsx/lite` instead of `clsx` (enforced by ESLint).

### `pages/` layer

Leave the `pages/` layer as-is — it is managed by TanStack Router's file-based routing. Routes live under `src/pages/` with TanStack Router conventions (`_authenticated`, `__root`, etc.). The route tree is auto-generated into `src/app/routes/routeTree.gen.ts`.

### `shared/` layer

Not divided into slices — organized by type: `api/`, `components/`, `const/`, `hooks/`, `lib/`, `types/`, `ui/`, `utils/`.

Slice-like modules under `shared/ui/` and `shared/components/` follow the same file-naming convention as the rest of the project: a public entry `{scope}.entry.ts`, plus `{scope}.component.tsx`, `{scope}.const.ts`, `{scope}.contract.ts` as needed. Import them via their full entry path (e.g. `@/shared/ui/button/button.entry`).

By-type folders that are not modules — `api/`, `lib/`, `hooks/`, `utils/`, `const/`, `types/` — use plain descriptive filenames (e.g. `use-auth.ts`, `api-instance.ts`) and are not held to the `{scope}.*` pattern.

### `widgets/cross/` and `features/cross/`

The `cross/` sub-directory holds modules genuinely used in 2+ different slices. Don't put single-use modules there.

## API

- Axios instance at `src/shared/api/api-instance.ts` — `baseURL` points to the backend, attaches Bearer token from `localStorage` automatically.
- TanStack Query is the data-fetching layer; query client config lives at `src/shared/api/query-client.ts`.

## Commit conventions

Conventional Commits enforced by commitlint. Allowed types: `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `revert`, `style`, `test`, `translation`, `security`, `changeset`. Subject must be lower-case, no trailing period, max 100 chars.
